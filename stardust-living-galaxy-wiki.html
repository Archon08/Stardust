The one-line idea

SWG didn't lack systems. It lacked an operator.

Star Wars Galaxies shipped a galaxy of deep, interlocking systems — resources, ecology, crafting, the Galactic Civil War, a player-run economy — and then left almost every one of them running as a static table or pure RNG, with no feedback loop. No 2003 MMO could afford a human ops team watching every subsystem's telemetry around the clock, gently correcting drift. So the systems drifted. Resources went into month-long droughts. Hunting grounds went stale. One faction snowballed. Whole professions and schematics died unused.

A local language model is exactly the always-on operator those systems never had: it can read the real server telemetry that SWG generates but nobody analyzes, reason about the health and balance of each system, and act through bounded, deterministic tools the engine already exposes — continuously, offline, for free.

Why SWG is the ideal host

Cadence
Latency is a non-issue

Its systems move on minutes-to-days timescales. A model that thinks for seconds is invisible — the constraint that kills real-time LLM control simply doesn't exist here.

Tools exist
Nothing new to invent

Core3 already exposes the levers — the DirectorManager, ResourceSpawner, GCW and spawn managers. The agent drives functions the server already trusts.

Data-rich
Insight-poor by design

SWG servers overflow with telemetry no one reads. The model is the analyst-with-authority the data was always waiting for.

The thesis

SWG's genius was its interlocking systems; its tragedy was that they never adapted. A local model is the missing half — a resident intelligence that reads how the galaxy is actually being played and continuously, gently steers the knobs the developers set once and abandoned. One capability, many hats, one bridge.

The pattern

The model decides, off-tick. The engine executes, deterministically.

The whole design rests on one boundary. Real-time simulation — combat, movement, collision, the tick loop — stays 100% deterministic and synchronous. The language model never enters that loop. It sits beside the game as a slow, thoughtful advisor that emits bounded tool-calls, and the engine's existing, battle-tested scheduler carries them out on its own tick.

On-tick · deterministic
The engine keeps authority
  • Combat, pathing, collision, resource decay, event scheduling
  • Runs frame-to-frame with zero model involvement
  • If the model is offline, the vanilla game is unaffected
Off-tick · advisory
The model brings judgment
  • Reads aggregated state on a slow cadence (minutes–days)
  • Reasons, then calls a small allow-listed set of tools
  • Never touches state directly — only proposes actions

Where this came from — and why it collapsed to exactly this shape

This design didn't start with SWG. It was reasoned out for Guildborne, whose Rust engine (forge-game-server) has an L4D-style forge-ai Director that must fire every tick alongside worldevent and spatial. The original idea — put a local model in the Director's seat, letting it drive world-event timing, phasing (meteor showers), and boss/named encounters live — hit a hard wall: an LLM answers in hundreds of milliseconds to seconds; a tick is sub-frame. It physically cannot sit in the loop.

So it collapsed to the shape above: the model doesn't drive the loop, it makes coarse, low-frequency decisions off-tick and is handed bounded tools to schedule and trigger events, which the deterministic engine then executes. That collapse is the whole concept — and it's what carries, cleanly, into SWG.

Why SWG makes the hard part disappear

The Guildborne wall was latency in a per-tick action game. SWG is a persistent world where invasions, spawns, resource shifts and faction swings unfold over minutes to hours. The exact obstacle that forced the collapse is simply absent here — which is why SWG is a far better host for the idea than the game it was invented for.

The engine reality that shapes the bridge

Two verified facts about Core3 dictate the seam. There is no outbound HTTP client in the C++ engine (no libcurl), and no Lua socket / os.execute in the script layer — so the game cannot synchronously call out to a model. That's fine, because the model is off-tick by design. What Core3 does have: an inbound mongoose WebServer with servlets, and full database access.

Game → model · state feed
Read-only, no engine change

The sidecar reads world state straight from the game DB (and the metrics module). Nothing to modify in the engine to give the model its eyes.

Model → game · tool ingress
The one real seam to build

A validated channel that turns a tool-call into a scheduled engine action. Two clean options: a DB command-queue table the server polls, or an authenticated servlet on the existing WebServer.

The safety boundary, restated

The DirectorManager is Core3's deterministic scheduler and executor. The model sits above it, off-tick, emitting allow-listed calls to a small subset of these functions. It decides what / where / when / how intense; the Director carries it out on-tick, exactly as it does for hand-written screenplays today.

Why the model must be local

Perpetual
Runs forever, for free

24/7 background stewardship billed per-token by a cloud API is absurd. A local model watches the galaxy continuously at zero marginal cost.

Private
Data never leaves the box

Server economy, player telemetry, and live config stay on-prem. No egress, no third-party exposure.

Sufficient
Small model, big leverage

The task is bounded judgment over pre-aggregated tables. A small tool-calling instruct model (Qwen / Llama / Mistral class) is enough once the numbers are summarized.

S-01

Resource Economy Steward

Emergent, player-drivenRNG droughtsDead low-tierMarket opacity

The flagship. SWG's resource economy was its most singular system — and its most neglected. This steward is the missing economic feedback loop.

Resources spawn galaxy-wide with randomized stats, each class rolling within its own min/max caps, at random concentrations, for a limited duration, then despawning. Surveyors hunt the good spawns; crafters buy them; the bazaar prices reflect stat quality. That interdependence is the magic — but it ran on pure RNG with nobody minding the store.

The eleven resource attributes it reasons over

OQ Overall QualityCR Cold ResistCD Conductivity DR Decay ResistHR Heat ResistMA Malleability PE Potential EnergySR Shock ResistUT Unit Toughness ER Entangle ResistFL Flavor
Reads
  • Live pool & spawn history (resourcepool/resourcemap): what's active, each spawn's stats, concentration, time-remaining, and when each class last appeared → droughts & stat gaps
  • Market (AuctionManager): listings, quantities, prices, trends → real shortage vs glut
  • Revealed demand: harvester placements + crafting consumption → what the economy actually eats
  • Population of active crafters/harvesters → scale supply to the live server, fixing the 2003-config mismatch
Does
  • Drought relief — a needed class absent too long → createResourceSpawn it with sensible stats/duration
  • Targeted windfall — no usable-stat instance of an in-demand class exists → inject a rare high-quality spawn
  • Low-tier floor — guarantee entry-level resources are always available at usable quality (an onboarding lever)
  • Pool tuning — adjust active type count / spawnThrottling to match population
  • Curve shaping — bias randomizeValue so low-tier isn't garbage and windfalls stay rare
  • The scarcity report — publish a readable galaxy resource digest via the news layer
Worked scenario

It's been 19 days since any Duralloy Steel spawned above 900 OQ anywhere in the galaxy. Weaponsmiths' consumption of steel has spiked; the bazaar shows zero high-stat listings and prices up 340%. The steward flags a drought, and in Propose mode drafts a single windfall spawn — a rich, high-OQ Duralloy vein on Dantooine, 5-day duration — plus a news line: "Prospectors report a rich ore strike in the Dantooine highlands." Surveyors scramble; the crafting line unblocks; the treasure-hunt feel is preserved because the windfall is rare and temporary.

S-02

Creature Ecology Steward

Rich species & lairsDynamic spawnsStatic tablesStale hunting grounds

Keep the wilds alive and level-appropriate. A galaxy where the ecology never responds to the hunters is a galaxy of dead farm spots.

SWG creature spawns are region/heightmap tables with lairs and a DynamicSpawnObserver layer. Rich, but static — players farm a grove to death and nothing changes; some XP bands have no good grind; some regions overflow while others sit empty.

Reads
  • Kill / spawn density telemetry per region and species
  • Player level bands active vs the spawns available to them (XP-appropriateness gaps)
  • Lair destruction rates; over- and under-farmed zones (Dathomir, Endor, Lok, Yavin IV…)
Does
  • Migrate populations & freshen farmed-out grounds via spawn adjustments and spawnMobile
  • Guarantee a viable grind exists for every level band
  • Stage ecological events — predator booms, herd migrations, a rancor overpopulation on Dathomir — as timed createServerEvent beats
Worked scenario

Telemetry shows the Nym's Stronghold approach on Lok has been ground to a barren strip — thousands of kills, spawns can't keep pace, and the 40–50 band has nowhere fresh to hunt. The steward proposes a short "kimogila stirring" event deeper in the Lok wastes: a denser, slightly tougher spawn cluster with a named alpha, drawing hunters off the dead strip and letting it recover.

S-03

Mission Supply Steward

Infinite procedural missionsMad-lib repetitionPayout drift

Give terminal missions a reason to exist — and keep their economy honest.

Destroy, delivery, crafting, entertainer and bounty missions are RNG coordinate-shuffles disconnected from the world. The mechanics are fine; the authorship and balance are absent.

Reads
  • Which mission types players actually take, complete, or abandon
  • Payout-per-effort drift vs the rest of the economy (feeds the Credit Steward)
  • Under-used zones and content that could be steered toward
Does
  • Authors mission premises & flavor over the existing mechanics (mechanics stay deterministic)
  • Retunes reward tables toward balance; points players at neglected zones/content
  • Chains a few missions into a small emergent arc without a designer writing a quest
Worked scenario

A destroy mission stops being "kill lair at /waypoint" and becomes: "The Whithorn moisture farm outside Bestine is being overrun and the militia won't answer. Clear the nest." Three such missions from the same terminal quietly reference the same escalating raider threat — an arc that emerged from the steward, not a script.

S-04

GCW / Faction War Steward

ImperialRebelPersistent PvP warSnowballingSilent zones

Keep the war a war. A Galactic Civil War that one side has already won is just a map.

The GCWManager runs base vulnerability windows, troop spawns and destruction — persistent and player-driven, but with no hand on the scale when a faction snowballs or a contested planet goes quiet.

Reads
  • Faction population balance & online split; GCW scores per planet
  • Base activity, contested-zone traffic, recent PvP hotspots (Restuss-style flashpoints)
Does
  • Directs invasions/vulnerability toward quiet or contested zones (startVulnerability, spawnTroops)
  • Incentivizes the losing side; stages counter-offensive events
  • Rallies via faction propaganda through the news layer (broadcastToGalaxy)
Worked scenario

Imperials outnumber Rebels 3:1 this week and Rebel planetary control is collapsing. The steward doesn't hand Rebels a win — it stages an opportunity: a vulnerable Imperial supply depot on Talus with elevated rewards, plus a Rebel-side broadcast: "Imperial overextension leaves the Talus garrison exposed — strike now." A concentrated objective pulls the outnumbered side together instead of letting them log off.

S-05

Credit Economy Steward

Deep sink/faucet webInflationNo central bank

Mind the money supply. Every long-lived MMO economy inflates; SWG had no one watching the faucets.

Reads
  • Credit faucets (mission payouts, loot, NPC sales) vs sinks (fees, decay, insurance, travel)
  • Aggregate money supply trend; bazaar price inflation across staple goods
Does
  • Recommends faucet/sink adjustments to hold currency stable (in tight coordination with the Mission Steward's payouts)
  • Flags anomalies — sudden money-supply spikes that suggest duping or an exploit — for operator review
Worked scenario

Staple bazaar prices have crept up 22% over a month while mission payouts held flat — classic slow inflation from loot faucets outpacing sinks. The steward reports the trend and proposes a modest, temporary decay/fee nudge rather than a jarring payout cut, keeping the change invisible to the average player.

S-06

Dead-Content Revival Steward

Vast schematic/profession spaceMost never used

SWG's content graveyard is enormous. This steward walks it and brings the interesting dead back.

Reads
  • Schematics never crafted, professions never taken, loot never bought, POIs never visited
  • Why they're dead — no viable resources? no demand? no reward? — cross-referenced with the other stewards' data
Does
  • Manufactures demand: an event that needs a dead item, a resource spawn that finally enables a dead schematic, a mission that rewards a dead profession's output
  • Coordinates with Resource + Mission stewards so revival is systemic, not a one-off handout
Worked scenario

A whole tier of Chef buffs is never made because their reactive-gas ingredient hasn't spawned usable in months. The Dead-Content Steward connects the dots the individual systems can't: it asks the Resource Steward for a gas windfall, then seeds an entertainer/cantina event that consumes those buffs — reviving a dead schematic and a dead social loop in one move.

S-07

Encounter Tuning Steward

Heroics & world bossesStatic difficultyPower-curve drift

Keep the hard content hard. Player power creeps as the meta is solved; static encounters don't.

Reads
  • Clear-times, success/wipe rates, and group compositions on heroics (Axkva Min, Exar Kun, IG-88, Tusken King) and world bosses
  • How those metrics drift week over week as players optimize
Does
  • Recommends encounter tuning to the actual playerbase power curve (within designer-set bounds)
  • Proposes fresh mechanics/phasing for content that's become trivial
Worked scenario

Axkva Min median clear-time has fallen from 40 minutes to 9 as the community nailed the buff stack. The steward flags the trivialization and proposes — for operator approval — a modest add-phase or spawn-density bump that restores the intended challenge without a balance patch cycle.

S-08

World Liveliness Steward

Vast handcrafted worldEmpty planetsPopulation clumps

A galaxy where everyone stands in one cantina is a small galaxy. Spread the life out.

Reads
  • Where players actually congregate vs the huge swathes of empty world (whole planets, POIs, player cities)
  • Time-of-day and population patterns per hub
Does
  • Seeds activity in dead zones — spawns, NPCs, rumors, small events — to pull population outward (spawnMobile, spawnTheaterObject, createServerEvent)
  • Feeds the news layer so players hear a reason to go somewhere new
Worked scenario

Rori is a ghost planet — 2% of the population, ever. The steward stages a recurring "Narmle relief caravan" node: a cluster of NPCs, a small defend-the-convoy event, and a rumor broadcast. Not a mega-event — just a steady reason for a handful of players to make Rori part of their week.

S-09

Player Lifecycle Steward

Deep long-horizon progressionSilent churnNo personalization

The live-ops community manager SWG never staffed — reading each player's arc and nudging at the right moment.

Reads
  • Login cadence, progression stalls, content a player has and hasn't touched
  • Signals of imminent churn (lengthening gaps, abandoned goals)
Does
  • Tailored, in-fiction nudges via sendMail: a returning-player welcome beat, a personal mission, "the resource your character crafts with is back in supply"
  • Coordinates with Resource/Mission stewards so the nudge is true — the thing it points at actually exists right now
Worked scenario

A Master Architect hasn't logged in for 11 days; before that they were grinding toward a specific structure but kept getting blocked on a scarce ore. The steward waits for that ore to be in good supply (Resource Steward), then sends an in-character message from a "supplier contact": the material they needed is finally flowing. A reason to come back, grounded in the live world.

N-01

World-Event Director

Native event systemDirectorManagerSpace / JTL

The direct port of the original Guildborne concept — an intelligent live-ops GM that never sleeps.

SWG already has a human-driven eventPromoter and a full event system (seasonal Life Day, elections, races). This is its automated, reactive successor: it watches server state and decides what event, where, when, how intense, then schedules it through the Director.

Reads
  • Population per planet/sector, GCW pressure, recent activity, and crucially — what is not being played
Does
  • Schedules invasions, named/boss spawns, and theater events (createServerEvent, spawnTheaterObject)
  • Directs space events too — asteroid storms, pirate ambushes, squadron patrols (spawnShipAgent, spawnSpaceActiveArea). Your original "meteors" example, now in the JTL layer
Worked scenario

The Kessel sector has been dead for days while ground Tatooine is overcrowded. The Director stages a pirate flotilla incursion in a quiet Kessel run with escalating phases, spawns the ship agents, and broadcasts a distress call — pulling pilots into space content that was sitting unused.

N-02

Living News & Rumor Layer

Zero mechanical riskText onlyCheapest first proof

The voice of the galaxy. It says out loud what every other steward is doing — and it's the safest thing to ship first.

Reads GCW state and player deeds and writes faction propaganda, planetary rumors and NPC-bark text through broadcastToGalaxy / sendMailToOnlinePlayers. Pure text, no state change, can even run pre-baked — which makes it the ideal end-to-end test of the whole pipeline at zero risk.

Reads
GCW scores, recent notable player deeds (rare kills, base captures, PvP flashpoints), and the other stewards' actions to narrate
Does
Publishes in-fiction news, rumors and propaganda; gives every world-event and resource shift an in-world reason
Worked scenario

A player bounty hunter clears a notorious krayt dragon two zones away. Minutes later, cantina rumor NPCs murmur about it, and a faction bulletin references the "cleared threat on the Tatooine dune sea." The world referencing real player activity back at players — the thing Live never did.

N-03

Dynamic NPC Dialogue

Separate trackconv_handler.luaNeeds caching + canon

NPCs that are actually people — a distinct track with a different latency profile and higher canon risk.

The conversation seam is real and clean: ConversationManager + conv_handler.lua's getNextConversationScreen. A local model can author dialogue screens with persona, mood and memory instead of static trees. But this is per-player and turn-based, so it needs response caching and tight canon grounding — a separate build from the off-tick stewards.

Reads
Per-NPC persona + lore pack, the player's prior interactions, and current world/faction state
Does
Generates dialogue screens + options at the conversation seam, always with a static-tree fallback on timeout
Why it's a separate track

Turn-based generation is player-facing and latency-sensitive (needs a cache), and canon-fidelity risk is highest here — a hallucinating NPC in a beloved emulator is worse than a silent one. Park it behind the systems stewards; it does not share their off-tick, zero-latency safety profile.

What would need doing

The plumbing is small. The calibration is the real work.

1 · Read path
The aggregator

Queries that roll raw Core3 tables (resource pool, auctions, spawns, kills, GCW, players) into a compact "state snapshot" the model can reason over. Read-only, no engine change. This is more work than the model call itself.

2 · Model + prompts
The local sidecar

A small tool-calling instruct model + a per-steward system prompt + an SWG lore/config grounding pack so every proposal is canon-valid and config-valid.

3 · Tool ingress
The one real seam

A DB command-queue table the server polls, or an authenticated servlet on the existing mongoose WebServer. It calls existing Director / spawner / GCW functions — no new gameplay primitives.

4 · Guard layer
Allow-list + caps + audit

Per-steward allow-list, hard caps, rate limits, full logging, and the Report→Propose→Act posture gate. This is where trust is enforced.

The genuinely hard part — say it plainly

It isn't the plumbing. It's calibration. "Balanced" is a value judgment that needs your targets: how flat a floor, how rare a ceiling, how interventionist. And the demand telemetry is imperfect — harvester placement is a proxy; consumption may be thinly logged.

The real risk is over-correction: too much stewardship kills the player-driven market and the thrill of finding a great spawn. The model must smooth the floor (no infinite droughts, no dead low-tier) without flattening the ceiling (windfalls stay rare and exciting). Getting the light touch right is the whole game.

The community constraint (matters more than any code)

Stardust's identity is Live-faithful. So every steward is additive and opt-in — layered on custom/Stardust content and ambient life, never overwriting canonical Live spawns, quests or behavior. Framed that way, this adds the one thing Live never had — a reactive, living galaxy — without touching the faithfulness claim. And transparency is the shield: the public scarcity report frames resource stewardship as drought relief + visibility, never "GMs handing out materials."

The trust ladder

Prove the pipeline once at zero risk. Then grow one hat at a time.

0
Read-only report No risk

Pick one front (the galaxy scarcity report is ideal) and ship it read-only. It exercises the entire read-path + aggregator + local-model reasoning pipeline with zero authority over game state, and delivers value on day one by fixing opacity.

1
Living News & Rumor Text only

Turn on the news layer — still text-only, via broadcastToGalaxy/sendMail. Proves the full sidecar + state-feed + guardrail loop end-to-end with no balance risk. The galaxy starts to murmur.

2
First acting steward Bounded

Widen the allow-list from "text" to "spawn/schedule" for one system — the Resource Steward's drought relief and low-tier floor are the highest-value, most-loved target. Starts in Propose mode under operator approval.

3
Grow hats Bounded

Each additional steward — Ecology, GCW, Director, Liveliness — reuses the exact same bridge. New prompt, new allow-list, earned trust. The World-Event Director and Space events slot in here.

4
Separate track: Dynamic NPC Dialogue Own build

The conversation seam — per-player, cached, canon-grounded — is its own effort with its own latency profile. Kept deliberately behind the systems stewards.

Where it all lands

You end with a coherent three-agent-class, one-bridge design: systems stewards that tend the galaxy's machinery, a narrative layer that gives it a voice, and — eventually — NPCs that talk back. All off-tick, all local, all driving tools Core3 already trusts. SWG didn't lack systems. This is the operator it lacked.
